# A7C II 2.01：SSH 与故障后的网络可用性

本成果合并 SSH 可行性与实测，以及共享库损坏时 Wi-Fi 控制面的容错调查。

| 文档 | 内容与证据边界 |
|---|---|
| [统一报告](REPORT.md) | §1–§8：SSH 限制、独立实例实测、账户改动及还原；§9：共享库损坏后的网络可用性 |
| [范围与授权](scope.md) | 区分最初调研、后续授权实测和离线故障研究 |
| [SSH 启停脚本](ssh-camera.sh) | 历史实测流程的工具封装；主机参数由调用者提供，通用版与 stop 分支尚未完成实机回归 |

**SSH 部署会写相机文件，不是零写入方案。** 载荷和邮箱会写 `/tmp/jiritsu`，
部署还涉及运行目录；历史取得 shell 的实测修改过 `/etc/passwd`，详情见主报告 §8。
不要在要求相机只读的采集任务中自动运行启停脚本。

报告的故障分析不构成网络救援保证：模块加载失败后继续初始化，不等于 Wi-Fi 自动关联成功，
更不等于应用损坏后 SSH 一定可用。没有在真机上破坏、截断或替换共享库来验证。

历史会话证据留在本地被忽略的 `evidence/`；私钥由主机管理，不随成果提交。
