# 相机固件里藏着开发者模式吗？——藏着，但被索尼"阉割"了一半

**这份调查回答一个问题：A7C2 的零售固件里有没有索尼工程师自己用的调试模式，
能不能为我们所用。** 全部靠离线反编译整机 dump 得出结论，没在真机上切换过任何模式。

详细技术报告在 [REPORT.md](REPORT.md)，这页只讲重点。

## 有什么

固件里确实有一整套工程模式，像一栋楼的"设备层"：

- **启动分层开关**（dmode）：可以命令相机"只启动到第几层"——只起系统、起到驱动层、
  起到底层运行时、或完整启动。坏了能一层层排查，对 QEMU 模拟器项目特别有用。
- **内存医生**：自带 LeakTracer 和 jemalloc，能抓相机主程序的内存泄漏——这两个真的能用。
- **串口控制台开关**：零售机把串口输出关了，但留个了"暗号"文件
  （`/setting/development.txt` 里写 `DEV`）就能重新打开。
- **工程更新模式**：可以同版本重刷、可以降级——但**不能刷自制固件**，签名校验照样拦。
- **售后诊断通道**（senser，USB 服务模式）：能读写校准/备份数据，但高危命令都被锁了。
- **一箱工程工具**：26 个原厂测试插件（能驱动录像、屏幕、音频等做单项测试）、
  调整数据工具、内部状态观察工具。

## 但有一半是摆设

索尼发布零售固件时把不少模式"去势"了——**开关还在，里面的东西拆了**：

- 号称的 gdb 调试器模式：拼出来的命令根本到不了执行那一步，死路；
- 号称的"任意注入库"模式：实际只认 4 个固定文件名，想注入自己的库没门；
- KMC ICE、LIQUID、DUMA、"旧驱动"变体：代码里连处理分支都没有，纯死代码；
- 售后通道里的"读写内存""开终端""固件更新"命令：要么是空函数，要么直接被门禁拦下。

## 两个容易踩的坑（替后来者排雷）

1. **工程更新模式≠能刷自制固件**。所有更新路径过同一个 RSA 验签，自制包照样被拒。
2. **改区域码≠解锁语言**。语言开关在另一个存储区（Backup），和区域码没有关系，
   别在这条路上浪费时间。

## 那到底怎么用？

用 USB 服务模式**开不了**这些模式（"写启动模式"那条命令被门禁拦了）。
真正能用的路是项目已有的 root 入口（libJit）：拿到 root 后直接往设置分区写开关文件，
重启生效，不动只读分区，随时能改回来。

## 这份调查怎么做的

五条线并行查：启动器反编译、售后命令枚举、SSH 路径、更新器、冷门模式与工具箱。
所有结论标注了证据强度（代码证实/字符串证实/推断），没接真机、没改任何设置。
原始 dump 只读，挂载检查过的分区前后哈希一致。
