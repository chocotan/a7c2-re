# 2026-10-17 阶段进展：可操作原固件菜单，完整相机链尚未完成

本次公开的是离线 QEMU 实验的源码、构建/资产导入工具及技术记录。**不是完整相机模拟器，也没有已完成的拍照或录像功能。** Sony 原厂固件、设备私有配置和转储不随代码发布。

## 已完成的验收

| 项目 | 目前可确认的结果 |
|---|---|
| 原内核与应用 | 原Sony内核到BusyBox，原bootin/im/appFw运行；菜单通过原管理器生命周期进入 |
| 菜单像素 | 原控件、字体和图片资源参与绘制；显式软件GPE与Sony LZ77 CPU解码工作 |
| 帧消费与窗口 | 有锁复制、完整HOSDAP02提交与通知；ramfb和GTK实际画布与AP像素一致 |
| 输入 | 上下左右、确认、MENU、删除/C2帮助功能、右后拨盘双向，在指定菜单场景通过 |
| 日期确定键故障 | 原udate驱动加原BY_BOOT时钟初始化，读回并验证推进；用户输入及返回/重进/日期编辑页导航共123步通过 |
| 崩溃后的输入积压 | 连续监视跨命令串口异常，停止接收并清队列；11项host/mock测试及真实故障重放通过 |
| 虚拟文件存储 | 原Fsys写4096B，第二进程重挂读回，全4MiB磁盘校验、独立fsck及主机文件解析通过 |
| 可复现输入 | 固定2.01固件身份、干净ALLLANG配置导入、schema2固定集合/权限/链接检查 |
| 原生启动与构建 | 一键菜单入口，隔离GTK窗口，完整QEMU修改源码和离线构建流程 |

“确认键已验证”只说明报告中的入口通过，不能推广到所有相机菜单。删除/C2目前验证的是帮助页；F12保存的是界面快照。存储测试写入的是确定性测试数据，不能当作固件拍摄产物。

## 正在推进

- **正常拍摄启动**：已找到原开机事件 `0x01000090` 的producer与派发路径。真实UI线程栈证明已进入 `scr0039_boot_controller::process_power_on → boot_start_seq`，停在 `model_future::wait`；调用链关联原 `0x2a` 序列请求。后续需要恢复其真实完成条件，不能再只因日志没出现就认定事件未发送。
- **媒体状态链**：原RM配置、状态查询、订阅及MediaDetect接口已有证据；原Fsys可读写不代表该通知链已完成。
- **CP启动**：原A32字节已运行到首个boot handoff访问；已找到NOR loader的软件写入者，仍缺物理别名、模式位来源和完整启动时序。
- **实机外观**：正在依据机身背面/顶部参考设计原生控制面板；本次生产界面仍是现有控制区，新外观没有冒充已集成。
