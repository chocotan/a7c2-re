# 从原固件菜单到原生窗口

## 为什么只有 QEMU 窗口还不够

Sony 应用并不向 PC 的虚拟显卡绘制。原图形链使用私有 GPE、OSD 队列、LIRO 和 CP；取景、硬件编码与面板输出还有各自的依赖。旧 QEMU 构建也只有 none/curses 后端。因此工作分成了固件生命周期、实际像素生成、输出消费、标准虚拟显示和输入适配几个部分。

## 已接通的显示链

1. 原厂内核/initrd 和应用在隔离 QEMU 中运行。应用库和原始资源保持原样。
2. 通过固件已有的完整生命周期入口创建菜单，保留旧对象析构、构造、初始化、presenter 和原请求泵。
3. 显式软件 GPE 模型实际执行已核准的绘图请求。缺失的 LZ77 硬件解码由有边界检查的同格式 CPU 解码替代。
4. AP 输出消费者冻结元数据，在真实位图租期内复制像素，完整写入并读回校验单一 HOSDAP02 容器后才发完成通知。
5. 独立 `ramfb-viewer` 读取同一个已提交 inode，校验长度、几何、来源及全容器摘要，将 RGBA4444 在黑底合成为 XRGB8888。
6. 通过 QEMU virt 的标准 fw_cfg DMA 配置 `etc/ramfb`，由 QEMU GTK 真正显示。

虚拟 scanout 使用单独预留的 `[0x41e100000,0x41e600000)`，含两个缓冲槽和 DMA/config 区。这是仿真接口地址，不是 Sony 实体面板地址。

QMP 显示设备截帧已经与 AP 数据逐像素比较通过，包括菜单、下移、上移回卷、分类列和项目列五种画面。事务号可能只表示元数据更新；只有 `pixel_source_seq` 变化才说明来自新的像素提交。

## 输入分三层验证

原生 GTK 按钮及键盘 → QEMU 指定图形 console 的输入处理 → 私有单字节控制通道 → guest 原输入队列 → 固件语义处理 → 新画面。

基础映射：MENU `0x1ab`，确认 `0x1ac`，上 `0x3`，下 `0x30`，左 `0x15`，右 `0x1af`。按下为1、释放为0，使用 guest 50ms 短按。此前尝试的 `0x14000102` 并不是当前 UI 转换路径中的 MENU。拨盘必须按有符号增量或位置事件处理，不能套普通按键的 press/release。

删除/C2 使用 `0x1f8`，已验证菜单帮助页，未验证真实文件删除。右后拨盘（固件 Rear Dial R / REAR2）使用 `0x10000013`，左/右分别单发 `status=-1024/+1024`；二进制消息中的负数为 `0xfffffc00`，不附加release。干净 ALLLANG 的 `run-817r0blc` 和 `run-g5w7q0z1` 分别到菜单第2项和反向回卷第55项，AP与QMP像素一致。原生GTK的九个启用操作已验证点击、键盘、焦点、暂停和正常Quit。

最终重建程序的整机九步验证位于 `runtime/analysis/native-window-check/check-xqunv9ei`：启动、Enter、四方向、PageDown、PageUp、MENU，实际窗口与各次校验AP快照逐像素一致，正常Quit返回0。旧七步结果保留为历史证据。

发送完成只证明输入命令完成。控件有效还需证明固件处理了相应语义，并观察到合理的状态或画面变化。删除/C2 的实体键与名称为 CUSTOM2 的事件也不能混同；C1 与录像键还可能经过用户自定义绑定。

## 快照与可追溯性

串口同时承载导出和诊断日志。解码器只剥离明确识别的内核记录及固定格式的 headless 状态记录，保留严格 Base64、精确长度、结构和完整容器校验。未知干扰或数据损坏继续拒绝，不能通过猜补字节修出一张图。

原生 GUI 的独立测试覆盖按键、鼠标点击、焦点恢复、暂停/断线和退出。完整固件测试再比较真实窗口中的640×480画布与校验后的 AP 快照，两个层次分别记录。

## 主界面与拍摄链的当前边界

最外层 MENU 退出已观察到 shooting 初始化，随后又转入 boot；输出新空帧，所以窗口为黑色。这既不是正常拍摄主界面，也不能仅解释为“没有传感器背景”。主界面的信息层和状态依赖仍需恢复。

虚拟 CMOS、镜头/AF、编码器、媒体服务和存储各有独立契约。后续软件模型必须放在固件实际请求/消费的边界；只有固件确实参与编码或打包、写入并产生可检查文件，才能声称实现了拍照或录像。主机图片生成器或窗口录屏不能代替这条验收链。

## 干净复现

研究 rootfs 曾混入真实设备设置和实验残留，不能直接作为公开包。新的离线导入器固定校验2.01原镜像，从 initrd、usr、cp 和固件默认设置生成干净环境，明确区分原厂资产、修改 IMDB、虚拟身份卷与项目 overlay。QEMU 的完整改动也必须相对固定源包对账；旧单一 timer patch 不足以重建当前程序。

本说明记录当前已验证机制，具体可运行文件清单及最终测试结果随交付完成更新。
